# Сервис видеоконференций на Go

Аналог Яндекс Телемоста: комнаты до 10 человек, вход по ссылке-приглашению, очередь, чат, админ-панель.
Проектное описание: [docs/DESIGN.md](docs/DESIGN.md).

## Что готово

### Этап 1: учётки и админ-панель

- Вход по логину и паролю (argon2id, JWT на 15 минут и refresh-токен в httpOnly-cookie), ограничение попыток входа.
- Первый администратор создаётся при запуске из переменных окружения.
- **Админ-панель** (`/admin`):
  - регистрация пользователей (пароль можно сгенерировать), смена имени, сброс пароля, блокировка, удаление, назначение админов. Последнего админа удалить или понизить нельзя;
  - список комнат, состав и архив чата без входа в комнату, закрытие любой комнаты;
  - статистика за период;
  - просмотр таблиц БД только на чтение (без хешей паролей);
  - выгрузка всех данных в ZIP после повторного ввода пароля;
  - журнал всех действий.
- **Пользователь** (`/app`): создание комнаты (до 10 человек), ссылка-приглашение, завершение своей комнаты.
- Архив чата удаляется через 60 дней после завершения комнаты (настраивается).

### Этап 2: живая комната (`/r/<код>`)
- Гость вводит имя и встаёт в очередь. Зарегистрированные пользователи тоже ждут, без очереди входят только хост и админ.
- Окно управления хоста: очередь («Впустить», «Отклонить», «Впустить всех»), список участников (выключить микрофон или камеру, разрешить гостю микрофон и камеру, выгнать, сделать организатором), «Завершить для всех».
- Гости по умолчанию без микрофона и камеры. Включить их можно только после разрешения хоста или админа, выключить себе можно всегда. Запрет проверяет сервер.
- При выходе хост передаёт права зарегистрированному участнику или завершает встречу. Если хост пропал, комната закрывается через 5 минут.
- Админ входит без очереди и сверх лимита, виден с меткой «администратор». В админ-панели виден живой состав комнаты.
- Чат: история для вошедших позже, удаление сообщений хостом или админом, ограничение частоты.
- Обрыв связи: автоматическое переподключение, 2 минуты можно вернуться без очереди.

Кнопки микрофона и камеры пока меняют только состояние. Настоящие звук и видео (SFU на Pion и coturn) будут на этапе 3.

## Запуск в Docker

```bash
cd deploy
cp .env.example .env    # заполните пароли и секреты
docker compose up -d --build
```

Откройте `https://localhost` (для localhost сертификат самоподписанный) и войдите под `ADMIN_USERNAME` / `ADMIN_PASSWORD`.

На сервере укажите в `.env` свой домен (`DOMAIN=meet.example.com`), направьте на сервер DNS-запись и откройте порты 80 и 443. Caddy сам получит сертификат Let's Encrypt.

## Разработка

```bash
# PostgreSQL для разработки
docker run -d --name meet-pg -e POSTGRES_PASSWORD=dev -p 5432:5432 postgres:16-alpine

export DATABASE_URL='postgres://postgres:dev@localhost:5432/postgres?sslmode=disable'
export JWT_SECRET='dev-secret-dev-secret-dev-secret-dev'
export ADMIN_USERNAME=admin ADMIN_PASSWORD=admin-pass
go run ./cmd/server     # http://localhost:8080
```

Тесты (интеграционные тесты очищают схему `public` в указанной базе, используйте отдельную):

```bash
TEST_DATABASE_URL='postgres://postgres:dev@localhost:5432/meet_test?sslmode=disable' go test -p 1 ./...
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | — | строка подключения к PostgreSQL |
| `JWT_SECRET` | — | секрет подписи токенов, не короче 32 символов |
| `PUBLIC_URL` | `http://localhost:8080` | внешний адрес, из него строятся ссылки-приглашения |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | — | первый админ, нужны только пока админов нет |
| `CHAT_RETENTION_DAYS` | `60` | сколько дней хранить архив чата |
| `COOKIE_SECURE` | `true` при https | флаг Secure у cookie |
| `HTTP_ADDR` | `:8080` | адрес HTTP-сервера |
